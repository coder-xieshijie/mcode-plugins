# DSH 插件转换

把一个 DSH 插件转成 MCode 外观插件。判据只有一条：它能贡献的东西能不能对应到 MCode 的外观扩展点。全程只读源插件：不安装它的依赖，不执行、不 `require`/`import` 它的任何文件；转换由本 Skill 自带的 Node 脚本静态完成（只用 Node 自带模块）。

本文件所在目录记为 `SKILL_DIR`，脚本在 `SKILL_DIR/../../scripts/`。需要本机能运行 `node`（18 及以上）；运行 `node --version` 确认，没有就告诉用户先装 Node.js，不要改用别的方式执行源插件。

## 1. 确认输入

用户给的来源是下面三种之一，直接传给脚本：

- npm 包名（可带版本），如 `dsh-dream-skin`、`@scope/name@1.2.3`：脚本用 `npm pack --ignore-scripts` 下载到临时目录；
- GitHub 等 git 地址：脚本用 `git clone --depth 1`；
- 本地目录：直接读取。

来源不明确时只问这一项。

## 2. 转换并读报告

```sh
node "SKILL_DIR/../../scripts/dsh-import.mjs" <来源> --out <临时输出目录>
```

输出目录用系统临时目录下的新目录（如 macOS/Linux 的 `$TMPDIR/dsh-plugin-convert`，Windows 的 `%TEMP%\dsh-plugin-convert`），不要写进用户的项目。脚本打印拆解报告，并在输出目录写 `report.json` 和插件目录 `<输出目录>/<插件名>/`（内含 `CONVERSION.md`）。

脚本做的事（报告里会逐项写明）：

- 识别可静态解析的格式：`ctx.theme.register` 的字面量 token 表（如 dream-skin 内置皮肤、catppuccin 风味）、dream-skin 主题包、skin-center 清单 v2、带 palette 属性的 CSS 变量块（如 claude-style 的配色卡片）、opencode `theme.json`、PALETTE 色板字面量（如 bloom）。
- 把 `var()`、`color-mix()`、`oklch()`、`rgba()`、`calc()` 按 DSH 默认色阶求值成 `#rrggbbaa`，按映射表对应到 MCode 的 47 个颜色 token 和 9 个代码 token，缺的按规则推算，并把正文对比度调到 ≥ 4.5:1。
- 包内字体文件和内联字体转成 `fonts`；背景图片、视频转成 `wallpapers`；开机视频套标准开机页（进度条、就绪、片尾溶解进主界面、点击跳过）。
- `dsh-pet` 1.0 角色包（`pet.json` + `animations.json` + 图集）：图集原样放进 `pages/pet/media/`，页面按帧表（rect + durationMs）播放，按包里的 tags 把 idle / working / attention / success / error / greeting 接到会话状态上。同一包里有多个角色包时用最全的那个，其余进「其他没收录的」。
- 立绘 / 角色素材（文件名含 pet、mascot、character、live2d、立绘这类词）套标准桌宠页 `pages/pet`：点一下显示会话状态，双击开主窗口，右键有「打开主窗口 / 插件设置 / 去处理某个会话」，可以拖动，透明区域点击穿透。
- 生成的页面会推导出自己的插件设置项（开机页的开关、桌宠的开关）。
- 报告里有一张「对外观扩展点逐项对照」表，主题、字体、壁纸、开机画面、桌宠、设置、manifest 字段各占一行，写清产出、来源和说明——这是「这个插件能转什么」的正面回答；再后面才是「丢掉的」。
- 只有整包没有可搬内容时才整包拒绝（目前是 dsh-wallpaper-engine 这类素材必须实时渲染的）。其余插件逐项处理：能静态读取的照转，依赖宿主运行时的（如推理滑块联动、背景管理器、agent 工具）写进「丢掉的」，不要因此拒绝整包。

## 3. 在对话里给出拆解报告

用自己的话把报告讲给用户，三块都要有：

1. **能转什么**：把覆盖表逐行讲一遍——主题几套、各有哪些明暗模式（只有一种的应用时会锁定该模式）、字体、壁纸、开机画面、桌宠、设置项。**不要只说其中几项**：用户问的是「这个插件能转什么」，六项都要给结论，没有的也要说「没有」。
2. **丢什么**：毛玻璃、DOM 改写、音效、状态色和 diff 色等 MCode 接不住的部分，原样转述报告。
3. **许可**：哪些素材默认没打包、为什么（非商业 NC、未授权、出处不明）。

报告里有“等你确认许可的素材”时，问用户是否确认这些素材可以使用（例如是自己的、或已取得授权）。只有用户明确同意某一项，才把它的 id 加到 `--allow` 重新转换：

```sh
node "SKILL_DIR/../../scripts/dsh-import.mjs" <来源> --out <同一输出目录> --allow id1,id2
```

用户没点头的素材保持不打包；不要替用户判断“应该没问题”。opencode-palette 的 IP 主题胶囊默认不收录，用户明确要时加 `--include-capsules`。

报告末尾“自检失败”时，不要安装，把失败项告诉用户。

## 4. 问是否安装并启用

问用户：“是否安装并启用这个外观插件？”插件带开机动画时在同一个问题里说明：“它带开机动画，安装后会设为开机画面（替换现在的开机画面，下次启动生效），之后可以在插件设置区关掉。”带桌宠时补一句：“它带桌宠页，装好后在插件设置区点「显示桌面宠物」，同一时间只能有一个插件用桌宠。”用户同意后：

1. **确定 MCode 数据目录**：用当前会话环境信息里的 `activeDataDir`；当前会话里 `plugin-creator` Skill 渲染出的 `{{DATA_DIR}}` 路径与它相同，也可以用。两者都拿不到时问用户，不要猜 `~/.minimax`。
2. **安装**：

   ```sh
   node "SKILL_DIR/../../scripts/install.mjs" <输出目录>/<插件名> --data-dir <数据目录>
   ```

   插件会写进 `<数据目录>/plugins/<插件名>/`，MCode 自动扫描并默认启用，不需要重启。脚本退出码 3 表示同名插件已存在：问用户是否覆盖，同意后加 `--replace` 重跑。
3. **插件带开机动画时，设为开机画面**：安装成功后运行

   ```sh
   node "SKILL_DIR/../../scripts/open-boot.mjs" <安装脚本打印的插件目录> --open
   ```

   协议名由 MCode 放在命令环境变量 `MCODE_APP_SCHEME` 里，脚本自动读取（用户另外指定时加 `--scheme <协议名>`）。脚本输出一行 JSON：

   - `hasBootPage: false`：插件没有开机动画，跳过这一步，不要提开机画面。
   - `launched: true`：系统已接收“设为开机画面”的请求（MCode 收到后会把它设为开机画面，顶掉原来的，下次启动生效）。回复里说“已请求把它设为开机画面，下次启动 MCode 时生效；不想要可以在插件设置区关掉「用作开机画面」”。不要说已经生效，脚本无法确认 MCode 处理了它。
   - `url: null`（没有协议名）或 `launched: false`：不要说设好了，告诉用户手动路径 `manualPath`（插件管理 → <插件名> → 插件设置 → 用作开机画面）。

   这是唯一由你替用户做的外观选择，只在用户同意安装之后做。
4. **带用户去插件设置区**：

   ```sh
   node "SKILL_DIR/../../scripts/open-details.mjs" <插件名> --open
   ```

   协议名同样取 `MCODE_APP_SCHEME`。`launched: true` 只表示系统接收了链接，不代表当前这个 MCode 显示了详情页：说“已发出打开请求”，把链接和手动路径一起给用户，问详情页有没有出来；用户确认出来了，才能说“已打开”。`launched: false` 或没有协议名时，不要说打开了，只给手动路径“插件管理 → <插件名> → 插件设置”（有链接就附上链接）。

   告诉用户在插件详情页的插件设置区自己点：主题上的「应用」，字体上的「用作 UI 字体」「用作代码字体」（插件设置区的“UI 字体”“代码字体”下拉里也能直接选本机已装的字体），壁纸上的「用作壁纸」，开机画面上的「用作开机画面」，桌宠的「显示桌面宠物」。

**Agent 不替用户应用主题、字体和壁纸**：不改外观设置，不写 MCode 的数据库或配置文件；除第 3 步的开机画面深链外，只做安装和打开详情页。

## 5. 收尾

告诉用户：插件目录位置、`CONVERSION.md` 里有来源与版本、对应关系、丢失项和许可；以后不想用可以在插件详情页停用或卸载，外观会立即回到默认。
